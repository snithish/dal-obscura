Policy governs the read.
Arrow carries the result.

A visual map of the control plane, data plane, captured authorization, and streaming execution. C4 views move from system context to concrete code contracts.

Governance / controlRead executionState / contractsExternal systems

Plan once. Enforce on every read.

Planning captures source tasks, policy, projection, identity context, and expiry. Fetch re-authenticates the caller and executes that captured plan. Routine policy edits affect new plans; explicit revocation stops outstanding access.

Stateless workers; durable coordination.

No tenant/cell routing or global generations. PostgreSQL owns canonical policy and ticket exchange state. Workers keep only bounded provider reuse and transient execution resources. Startup-loaded auth/runtime/path settings require restart to change.

DATA FLOW · FILTER BEFORE MASK

Raw data becomes governed Arrow

Backend pushdown is an optimization. The final transform enforces the complete filter on original values.

Drag to pan · Ctrl/Cmd + wheel to zoom · double-click to fit · click to expand

Rendering…

The client receives only governed Arrow batches. WHERE and masking projection are parts of one row-local SQL query; boxes represent semantic order, not separate materialized tables. Hidden filter dependencies are removed from output. Arrow avoids unnecessary copies where supported; zero-copy is not guaranteed across every transform.

CURRENT GUARANTEES · OPEN BOUNDARIES

Where correctness lives

Final transform is authoritative

Backend pushdown never substitutes for the complete filter. Hidden execution columns do not appear in the result. Ancestor masks govern descendant projection. Advertised schema must match emitted Arrow batches.

Identity and ticket guards

Signature and expiry, stored payload hash, principal/issuer/context binding, atomic exchange reservation, and per-batch revocation/expiry checks all precede authorized output. Exhausted tickets remain until expiry so active exchanges can be revoked.

Recommended, not yet implemented

Data-only scan descriptors; keyed integrity for complete stored payloads; whole-request admission and aggregate memory budgets; cancellation propagated through blocked operations; bounded metadata planning; connection-level egress enforcement.

Executable evidence

Policy and row-filter unit tests; real DuckDB/Flight nested masking; ticket expiry and revocation; SQLite/PostgreSQL snapshot races; provider lease capacity/cleanup; plugin conformance and consumer parity. See contributor guidance for behavioral test ownership.
