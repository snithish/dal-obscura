Responsive behavior

At 390px, use one column and full-width input controls. Show field paths above their results. Wrap long strings instead of hiding their endings.

Let the preview use the available screen height, with one main scroll region. Keep its close action visible without covering focused fields.

At 200% zoom, the editor should reflow into one column. The save bar must not cover the current field. Return focus to the opener when a dialog closes.

Design target. Aim for 44px primary touch controls. WCAG 2.2 AA requires at least 24 by 24 CSS pixels or a qualifying exception. This mockup is not an accessibility certification. Read the target-size criterion.
06 / Recovery and trust

Explain what happened next.

These are proposed messages and recovery paths. The controls below simulate them locally.

Loading and empty

Keep loaded rows during refresh and announce busy status. Distinguish no search matches, no authorized assets, and a failed request. Never turn an error into a zero count.

Validation and local edits

Keep field values after rejection. Move focus to invalid input after submission. Explain unapplied mask and row-filter edits beside the blocked save action.

Identity and sign-out

Preserve capability checks and session cache clearing. Retain the unsaved-change guard and retryable logout. Keep synthetic identity previews clearly separate from sign-in.

07 / Implementation sequence

Deliver within existing owners.

Suggested order, not a calendar commitment. Relative effort assumes the current Mantine system and no new persistent subsystem.

Phase 1 · Small to medium

Clarify and repair

Unify default-policy language. Make connection errors local. Reflow the mobile value preview. Move bypass into an explicit advanced section.

  • Owners: assets, connections, RuleInsights, design/base.css.
  • Start each behavior change with an owning failing test.
  • Gate: current guards pass; desktop and mobile captures reviewed.
Phase 2 · Medium

Improve policy review

Add the rule summary and save review. Compare the baseline with the draft using existing policy state. Explain token behavior before submission.

  • Owners: AssetWorkspace, policy_draft, existing confirmation flow.
  • Keep canonical schema paths, parent masks, and revision fences.
  • Gate: conflict, unknown outcome, partial failure, and read-only journeys pass.
Phase 3 · Medium, API dependent

Improve discovery and administration

Add catalog and policy filters, readable activity actions, settings section navigation, and account-menu consolidation.

  • Owners: inventory queries, ActivityView, SettingsView, AppShell.
  • Confirm server filter support before promising whole-inventory results.
  • Gate: authorized counts, pagination, dirty drafts, and keyboard navigation stay correct.
Tradeoffs and decisions to settle before implementation

Review step: A modal adds one action. Keep it concise and compare comprehension with the current direct save. Do not require successful preview testing to save; that would create a new workflow rule.

Inventory filters: A filter over loaded rows is cheaper but incomplete. Prefer server-supported filters. If that requires an API change, scope and regenerate its contract before implementing the UI.

Summary scope: Derive a draft rule summary from existing state. Do not present it as combined authorization evaluation or create a new evaluation engine in the browser.

Owner labels: Use labels from existing authorized metadata. If a display name is unavailable, show the canonical principal or a safe abbreviation with full disclosure. Do not infer identity claims.

Save and revoke: Keep the current service contract. Surface each operation's actual outcome; a UI review step must not imply atomicity that the server does not provide.

08 / Validation and completion

Measure clarity before claiming gains.

Targets below are proposed acceptance criteria. No task-time baseline, usability score, performance improvement, or WCAG conformance has been measured.

Behavior and correctness

  • Test selected columns, nested scope, masks, and NULL behavior with the existing owners.
  • Retain unapplied edits, navigation guards, stale-response handling, and revision conflicts.
  • Cover save success, unknown outcome, rejection, and revocation failure separately.
  • Run UI unit tests, story tests, browser journeys, check, API-type check, and build when implementing.
  • Run relevant large-schema and mask performance journeys if summary or preview rendering changes.

Visual and accessibility review

  • Capture 1440px desktop and 390px mobile in light and dark themes.
  • Review keyboard order, dialog focus return, Escape, screen-reader announcements, and 200% zoom.
  • Check contrast, target size, readable identifiers, and focus visibility around sticky controls.
  • Keep before and after captures in docs/ui-review, outside correctness tests.
  • Use live SSO qualification if identity behavior changes. Synthetic routes cannot prove logout.
Proposed usability check. Ask at least five representative administrators or policy authors to find an asset, mask its email column for a group, and explain the save effect on existing tokens. Target at least four unassisted completions and five correct explanations of token behavior. Record errors and time against the current UI using the same tasks. These are proposed targets, not statistically established results.
What this review verified and what remains open

Completed: source inspection across the named flows, representative test inspection, four historical capture inspections, and pattern research. The HTML contains isolated interactive concepts, embedded evidence, and no application writes.

Limitations: app dependencies were absent. A frozen dependency install produced no output and was stopped. No fresh app render or application suite ran. CocoIndex initialization succeeded, but indexing could not write its daemon log under the sandbox, so source review used direct search. Existing captures may differ from the present app.

Next implementation gate: restore Node 24 and pnpm 12.3.4 dependencies, render the current app with disposable synthetic fixtures, and confirm these findings before changing product behavior. Full contrast, manual assistive-technology checks, and representative user feedback remain open.

Artifact verification: passed in a local headless Chromium browser at 1440px and 390px, in light and dark themes, with no page overflow. Search, combined filters, empty state, mask summary, save diff, token explanation, simulated save, recovery messages, Escape, and focus return passed. Four embedded images loaded and no JavaScript page errors were recorded. A 720px reflow check also passed. This is not a manual zoom or screen-reader audit.
