01

The intended product

Experience

Connect → govern → read

Operators configure references, understand policy effects, review admission, and recover from failure through guided UI and CLI flows.

Breadth

Catalogs × formats × storage

Keep adapters separate. Qualify each advertised provider/version and both CoW and MoR for every supported transactional format.

Correctness

Exact values, bounded work

Remove incidental name/depth caps. Preserve typed paths and nested semantics within visible, configurable resource budgets.

Scope boundary: a governed reader, not a new write service. Raw Parquet has no table-level MoR semantics. “All catalogs” requires an explicit provider inventory. Unlimited input cannot be promised by finite-memory dependencies.

02

Where the gaps are

P0 blocks broader support claims; it does not mean a critical vulnerability. The audit did not demonstrate a policy bypass.

8 findings shown

P0 · CONFIRMED · E01–02

Fixed schema ceilings

256-character field names, 64-level nesting, 10,000 schema nodes, plus independent SDK/HTTP/wire budgets. A constants-only patch would leave broken boundaries.

P1 · CONFIRMED · E03–06

Large-workspace friction

Rows are virtualized, but complete-schema flattening and search remain. Discovery gathers the entire inventory; selected chips and deep indentation need redesign.

P0 · CONFIRMED · E07

Delta scale limits

10,000-file and 64 MiB log bounds; snapshot-wide deletion masks with a 16-million physical-row budget. Column mapping is rejected.

P0 · QUALIFICATION GAP · E09

Cloud support needs live evidence

Official clients provide broad transports. S3-emulator proof does not qualify live AWS, Azure, and GCS identity renewal, quotas, TLS, or multi-host throughput.

P0 · CONFIRMED · E10

No hard process/cluster RSS guarantee

Per-stream DuckDB limits exclude native planning and Arrow allocations. Per-process admission does not establish deployment-wide fairness.

P0 · MIXED EVIDENCE · E12

Trust boundaries expand with adapters

Only environment secrets are currently admitted. Provider DNS/redirect behavior, credential rotation, and artifact provenance need explicit end-to-end proof.

P1 · CONFIRMED · E11

Routine deployment still needs setup

The new plugin workflow works around an initialized Compose target. Target JSON, partial catalog publication, ticket draining, and recovery remain operator burdens.

P1 · CONFIRMED · E13

Consumer recovery is incomplete

Custom Flight is not generic Flight SQL/JDBC/ADBC. Single-use tickets need an explicit retry-attempt design; distributed Spark renewal and types need qualification.

Evidence identifiers resolve to source links and precise caveats in the detailed plan. Iceberg v3 and Hudi are separate P2 expansion milestones.

05

Change the foundations together

Long and deep fields

  • Distinguish field names, scalar values, namespace segments, schema width, depth, and task payloads.
  • Preserve typed identity and metadata through policy, SQL, Arrow, HTTP, UI, and every consumer.
  • Keep budgets configurable; remove unsafe application recursion and test native dependency ceilings.
  • Probe beyond today's limits: 257+ character names, 65+ levels, and 10,001+ nodes. Never silently truncate.

Secure, scalable operations

  • Measure whole-worker allocation before deriving admission; include Arrow, native readers, deletes, and DuckDB.
  • Qualify provider socket destinations, secret rotation, plugin provenance, and log redaction.
  • Publish related catalog changes atomically where possible; otherwise make recovery resumable and explicit.
  • Keep workers stateless and caches bounded. New persistent subsystems require a separate design decision.

07

What closes the plan

Functional proof

Exact schemas and values, independent tasks, nested masks, pinned snapshots, real provider identity, and all advertised CoW/MoR storage cells.

No stale policy substitution, lost edits, silent truncation, hidden credentials, or full-table rescans masquerading as distribution.

Operational proof

Usability journeys, bounded saturation, measured RSS and IO, cancellation cleanup, repeatable deployment recovery, and qualification of the final artifacts.

Configured limits, measured envelopes, and missing support remain visible to operators.

Decisions to settle in Phase A

Named catalog/provider versions; whether raw Parquet remains exposed; Hudi release priority; cloud accounts and worker identity; acceptable dependency ceilings; supported orchestrators; benchmark workload envelope.

These refine implementation sequencing. This document does not authorize or claim completed implementation.
